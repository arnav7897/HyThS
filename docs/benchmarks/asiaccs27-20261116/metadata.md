# ASIACCS27 benchmark run metadata

- Source revision: branch `asiaccs27/bench`, HEAD `60c3a36`; worktree dirty, including untracked benchmark drivers. PDF SHA-256: `989c5b8217e6da18b93d4b79efc4f83ab817d8c58c808e40e028faa8e4b3d1d1`.
- Platform: Ubuntu 24.04, Linux kernel `7.0.0-42-generic`, x86_64; Intel Core i5-1240P, 16 logical CPUs, 12 physical cores. Timing runs pin to CPU 2 with one process/thread. Host controls clock scaling.
- Build: Release, GCC 13.3.0, `-O3 -DNDEBUG`, secp256k1, mcl and OpenSSL 3.0.13; `HTA_BUILD_BENCH=ON`, `HTA_BATCH_VERIFY=OFF`, `HTA_OPCOUNTERS=OFF`, generator cache on.
- Workload: `t=ceil(2n/3)`, exactly t selected keys, fixed 32-byte message, 10 untimed warmups per invocation, then 100 samples. Random synthetic roster keys are generated once per invocation; mask and nonce scalars use the production RNG; session IDs are unique within each run.
- HTA runs cover Table A: n={64,256,1024,2048,4096}, r=kappa; Table B: n=2048, r={0,9,12}. Each cell has 100 verified samples. Both signer modes are recorded. Setup, roster construction, key derivation, and generator setup are outside timed samples. PoP registration is measured separately.
- HTA protocol driver times proof commitments/folding/other prover work, nonce aggregation, simulated share checks and response aggregation, certificate verification, verifier V1/folding-scalar/V2 MSM/Schnorr stages, signer Round 1/Round 2 in both modes, and actual framed sizes. The serial proof-to-signature interval runs simulated signer nonce/share work sequentially in one process; it is not distributed latency or pure coordinator CPU.
- FROST comparison uses the repository's RFC 9591 Appendix E.5 self-tested driver, not the separate Zcash Foundation measurements in the historical report. It uses the same mcl secp256k1 arithmetic adapter and OpenSSL hashing/RNG as HTA. Runs cover n={64,256,1024,2048,4096}, matching t=ceil(2n/3), with 10 warmups and 100 samples. Dealer/Shamir setup and Lagrange coefficient preparation are outside timed samples. Every share and final signature are checked; the aggregate FROST timing includes all share checks and final verification.
- A dedicated registration driver measures PoP creation and verification per key, with 10 warmups and 100 measured keys. Still unmeasured: peak RSS, simulated network latency, and concurrent sessions. No operational concurrency claim is made.
- The original ~1.2 KB Round-1 request estimate is not valid for this wire encoding: each selected signer index is sent as a framed integer. The measured request is 37,263 B at n=4096/r=13 and 321,560 B at n=2048/r=0. Any compact S encoding needs a format decision and a separate benchmark run.
- A 71-row n=2048/r=0 exploratory run was stopped before the benchmark phase gate and retained as `pilot-interrupted-n2048-r0.jsonl`; exclude it from summaries. Core checks pass in Release/Debug/ASan/UBSan. A deterministic decoder smoke is not coverage-guided fuzzing, and TSan is unusable on this host because the runtime reports an unexpected memory mapping.
- Raw records are JSON Lines. Complete cells require at least 100 successful records; failures terminate collection. Earlier `pilot-*` files predate warmups/randomized roster inputs or use Debug and are excluded from report tables.
- Research measurements only; variable-time secret operations remain. These results do not establish security, production readiness, or a completed security audit.
